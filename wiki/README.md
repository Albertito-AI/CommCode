## Update and recovery procedure

Edit the versioned source. The existing `Publish project whitepaper to Wiki` workflow publishes source changes and responds to Wiki edits. Its summary reports `PUBLISHED`, `ALREADY_CURRENT` or `BLOCKED_UNINITIALISED`. A committed Markdown file alone is not a publication receipt. The workflow uses the repository-scoped token and no paid publishing service.

The publisher writes only its marked Whitepaper and a marked, additive Home section. Preserve the Whitepaper's `atlas-whitepaper:managed:v1` marker. Other pages and Home text remain protected; an existing unmarked Whitepaper requires reconciliation rather than overwrite. Pushes are non-forced, so concurrent edits require review.

Only if a later check actually reports an uninitialised Wiki should a maintainer follow GitHub's [initialisation instructions](https://docs.github.com/en/communities/documenting-your-project-with-wikis/adding-or-editing-wiki-pages) and create the first Home page. An authentication or network error alone does not establish that initialisation is missing. Review credentials, permissions and the actual failure before choosing a recovery action.

The publisher does not execute Wiki content, change repository visibility or confer new reuse rights. Its successful publication is evidence of distribution, not evidence of scientific validation.
